# Black Beard Enhanced：教訓

Black Beard（Topo Soft、1988年）を逆アセンブルして改良する中で学んだことで、ほかの MSX ゲームにも役立つものです。技術的な詳細は DOCUMENTATION.md にあります。

## 1. 毎ループ画面を確認する

1. **openMSX の検証スクリプト。** 転送のたびに VRAM（パターン、色、ネームテーブル）をゲームのバッファと比べ、エラーのあったループを数えます。いくつかのキー操作（横、縦、静止）と HB-20P、HB-F900、FS-A1ST/GT で動かすと、目では見えないバグが見つかります。最後だけでなく、変更のたびに実行します。
2. **失敗したら、どこかを検証スクリプトに言わせる。** おかしい3分の1区画・列・ラインを示し、そのループの変数（バンク、K、FINO、全体転送か部分転送か、文字数）を出させます。おかげで奇妙な色のバグが数分で見つかりました。原因は「FINO だけ変わった」という近道で、VRAM の並びが同じままだと仮定していたのに、ネームテーブルが元に戻ったばかりでした。
3. **どんな近道（「ここは変わっていないので送らない」）も、ほかに何も変わっていないことが前提です。** 画面を動かす方法を新しく加えたら、既存の近道をすべて見直します。

## 2. 入りきらないときの、メガロムなし 32 KB ROM

効果の大きかった順（ZX0 は Einar Saukas 作）：

1. **メモリ上で連続する部分は1つの圧縮ブロックに。** 例：8000h-83FFh と 8400h-CORTE。
2. **プレフィックス付きの ZX0**（`zx0 +N`）。RAM にすでにあるブロックの直後に展開するなら、圧縮ツールはそこからコピーできます。注意：展開中にその RAM が見えている必要があり、ROM のあるページは使えません。
3. **小さいものも圧縮する。** TEST.BIN と言語の表。
4. **目的地に直接展開する。** 例えばロゴはバッファを通さず 9470h へ。そのためには、そのとき見えている ROM の半分にデータを置く必要があります。
5. **2つの半分のルール。** ページ2に行くものは、ROM をページ1に置いて読む半分に入れ、逆も同様です。ページ3に行くものはどちらでも構いません。調整できる `CORTE` で大きなブロックを両方に分けます。各半分の空きバイトを `display` で表示し、すべての版（Kixx/Topo、ビルドオプション）を試します。圧縮率が違うためです。
6. 使われないコードを0で埋めても数バイトしか減らず、割に合いませんでした。

## 3. 空きメモリと Z80/VDP の落とし穴

1. **ゲームが使わないページ0の RAM。** BIOS なしで動くゲームなら、0040h-00FFh などの低い隙間にコードを置けます。長いプレイ中に書き込みウォッチポイントで探します。ローダー（テープと ROM）の両方がそこにコピーする必要があります。
2. **使われないテープローダー。** テープのゲームの多くはローダーのコピーを持っていて使っていません。空き領域です（ここでは A5CFh-A66Dh）。
3. **割り込みはポート 99h を読む。** VRAM アドレスの2バイトの間に割り込むと、アドレスがずれます。DI でアドレスを設定し、割り込みの状態を戻します（`ld a,i` / `jp po`）。このせいで、ステータス表示の点滅が瓶を赤く塗っていました。
4. **TMS9918：** 表示中は OUT の間に29〜31サイクル。`out (98h),a / add a,h / djnz` のループは31サイクルです。
5. **ローダーのスタック：** LOAD.BIN のスタックがある場所までコードが届いていないことを assert で確認します。

## 4. うまくいかなかったこと

**横スクロールのためにネームテーブルを回転させる**（新しい列だけを送る）：

- openMSX では1ループが146 ms から101 ms になり、検証スクリプトのエラーは0でした。
- テスター（araubi）は不採用にしました。MSX1 では見た目が悪いからです。パターンが3分の1ずつ届く間に、ネームテーブルが一度に変わってしまいます。
- **教訓：** 計測と検証スクリプトには、表示中の画面の見え方は分かりません。転送の手法を採用する前に、MSX1 の実速度かフレームごとのキャプチャで見ること。

## 5. 納品

1. **納品したものから作り直す。** 空のフォルダに展開し、ROM と同じ SHA-1 になることを確かめます。ソース一式に doble.asm が欠けていて、元に戻す必要が出るまで誰も気づきませんでした。
2. **送ったテスト版ごとにソースを残す。** ROM だけでなくソースのコピーも。テスター（araubi）が次の版を却下したら、作り直さずに戻れます。
3. **ツールも残す。** テスト用スクリプトと各テストのキー操作もソースと一緒に（ここでは `src/openmsx/` と `tools/`）。

## 6. MSX2・MSX2+・turbo R

1. **turbo R：スロット0は拡張されている。** テープの TEST.BIN は ENASLT で RAM を探し、A8h とページ3のサブスロットしか戻しません。turbo R ではページ0が BIOS なしのままになり、最初の割り込みで止まりました。起動時に SLTTBL（FCC5h）を保存し、EI の前にスロット0のサブスロットを戻します。turbo R（002Dh ≥ 3）では CHGCPU 81h（R800 ROM）を呼びます。C-BIOS だけでなく、必ず turbo R の実 BIOS で試します。
2. **V9958：R#23（縦スクロール）はスプライトも動かす。** スプライト属性テーブルの Y に R23 を足します。D0h になったら D1h にします。D0h はリストの終わりだからです。R25/R26/R27（横）では符号なしで比べます（`jp m` ではなく `jr c`）。そうしないと右端で飛びます。
3. **MSX2+：テスター（araubi）は、ハードウェアスクロールを隠すための枠の描き直しを却下。** 見た目が悪いからです。画面内に枠とステータス表示があるゲームなら、すべての MSX で同じ、よくできたソフトウェアスクロールの方がよいでしょう。
4. **よい手本：MSX2 版 Pac-Mania。** マップ全体をページ2-3に描いておき、毎フレーム HMMM でウィンドウをコピー、LMMM TIMP でキャラクターを描き、R#2 でページを切り替えます。約7.5フレーム/秒、X は2ドット、Y は6ドット単位。枠とステータス表示は一度も描き直しません。
5. **MSX2 の裏画面**（doble.asm）：VRAM のバンクを2つ使います。見えない方に転送し、終わったら割り込みで R2/4/5/6/10 を切り替えます。描きかけは見えません。

## 7. テンポと速度の比較

1. **補正付きのリミッター。** 各ループを最低 N フレーム（ここでは 5 = 100 ms）にします。あるループが長引いたら（スクロール）、平均に合うまで次のループを縮めます。ゲームは MSX1・MSX2・turbo R で同じ速さになり、遊べないほど速くはなりません。turbo R では R800 のおかげでスクロールを細かくできます（6 ではなく 1）。
2. **オリジナルと新版を同じキー操作で比べる。** メインループにブレークポイントを置き、時間とプレイヤーの位置を記録します。結果は1ループのフレーム数と % で（Black Beard：9.30 → 5.25 フレーム、時間 −44 %、毎秒のループ数 +77 %）。スクロールでループが増えることもあるので、実際の移動（X ドット進む時間）も測ります。それぞれの版のキーを使います（オリジナルは Q/A/O/P）。

## 8. 何時間も節約できたテストツール

1. **オリジナルのテープを待たずに読み込む。** TAPION（00E1h）と TAPIN（00E4h）にブレークポイントを置き、Tcl から .cas のバイトを渡します（`src/openmsx/cinta.tcl` ＋ `cas_prep.py`）。数秒でゲームが始まり、開始時のオリジナルの RAM もダンプできます。
2. **テスターの .omr リプレイ。** gzip した XML で、RAM と VRAM を含むスナップショットが入っています。新しい ROM でバグを再現するにはスナップショットを入れます。録画後に ROM が変わっていたら、その RAM をそのまま入れてはいけません。録画に使った版（同じ SHA-1）を作り直し、2つのビルドで違うバイトだけを移植します。
3. **RAM からマップを作る。** 開始時のゲームの RAM と、Python に移したタイル描画ルーチンで、全体マップを PNG にできます（herramientas/mapas.py と mapas_original.py）。
4. **PSG の表による効果音。** 各項目はペアの数と、レジスタ／値のペアが続きます。数がペアと合わないと、存在しないレジスタに書き込みます。「砲声」はノイズ（R6）、3声すべてエンベロープ（R8-R10 = 10h）、ゆっくりの R11-R13、ミキサー 04h です。
5. **描画を疑う前にゲームのロジックを確かめる。** 「松明が消えない」の原因は、カメラが大砲の条件（ウィンドウがいちばん上）を崩していたことでした。オリジナルのルーチン（ここでは LB8FC）が何を必要としているかを読み、新版がそれを壊していないか確かめます。

## 9. MSX1 のスクロールと転送：行単位の転送

araubi は Black Beard の「行単位の転送」を MSX1 の基本として承認しました。うまくいったこと：

1. **転送に合わせたネームテーブル。** ゲームが画面を列単位で組み立てている（文字 = 列 x 8 + 行）なら、ゲーム中は別のネームテーブル（VRAM の別の場所、R#2 を変更）を使い、文字の各行を VRAM で連続させます。すると1行を一度に送れて、描きかけに見えるのは最大1行です。画面を消すときや、ゲームが独自にパターンを書くとき（メニュー、テキスト）は元の表に戻します。
2. **同じ行のパターン、色、スプライトをまとめて。** まず行のパターン、次にその色、次にその高さで変わるスプライトの属性。「色のずれ」（新しい絵に古い色）がなくなり、スプライトが違う背景の上に乗ることもありません。
3. **スプライトは固定の枠に。** 古いものを枠 0..N-1 に、新しいものをその後ろに隠して（Y=BFh）置き、各行では Y のバイトだけを変えます（新しいものを表示、古いものを隠す）。行ごとの連結リスト（最初／次）で32個全部を見ずに済みます。入りきらない（古いものと新しいもので32を超える）ときは、表を行ごとに書き直す方法に戻します。
4. **必ず測る：** 全体転送の時間（openMSX のブレークポイント）と、客観的なエラーの指標（違うインクの上のスプライトのドット数）。2322ドットから658ドットに、時間は5 %増でした。
5. **TMS9918：最速のループでも OUT の間に29サイクル必要。** 25サイクルのループは MSX2 では動き、MSX1（実機・エミュレータ）では失敗しました。NOP を足します。
6. **sjasmplus は define を別の名前の中でも置き換える**（-DFILAS で VOLCADO_FILAS が壊れた）：ラベルに出てこない名前を使います（PORFILAS）。
7. うまくいかなかったこと：横の一歩のためにネームテーブルを列単位で回転させる（lateral.asm）。MSX1 ではとても見た目が悪いです。画面全体を一度に変える小技より、1フレームの仕事を減らしてきちんと順序立てる方がよいのです。

## 10. 64 KB ROM は必ず ASCII16

32 KB の ROM が足りなくなり、Konami メガロムの 64 KB にしたところ、BlueMSX で起動しませんでした。BlueMSX は 64 KB ROM のメガロム方式を推測せず、4000h に「AB」がなければ ASCII16 とみなします。openMSX はメガロムのレジスタへの `LD (nn),A` 書き込みを数えます。ASCII16 にして `LD (77FFh),A` でバンクを切り替えれば、どちらも自動で認識します。注意：ASCII16 のレジスタは 6000h-7FFFh にあるので、バンクの切り替えは ROM がまだページ1に見えている間に行う必要があります。
