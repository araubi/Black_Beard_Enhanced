# Black Beard Enhanced：技術資料

Black Beard（Topo Soft、1988年）の MSX 版について、逆アセンブル、ゲームの中で見つかったこと、改良版（Enhanced）で変わった点をすべて説明します。ソースコードのラベルとコメントはスペイン語で、ここではコード中の名前をそのまま使います。

## 1. オリジナルのゲーム

### クレジット

[Computer Emuzone](https://computeremuzone.com/ficha/242/black-beard&pg=manual) によると：

* プログラム：Carlos Arias Alonso
* グラフィック：Roberto Potenciano Acebes（ゲーム中の表記は「ROBERTO P. ACEVES」）
* 音楽：César Astudillo（Gominolas）
* パッケージ絵：Alfonso Azpiri
* サポートソフト：José Manuel Lazo
* 販売：Erbe Software

ロード画面には「-ACE-」の署名があり、おそらく Roberto Potenciano Acebes です（未確認）。

### 知られているバージョン

| バージョン | 内容 |
|---|---|
| `Blackbeard (1988)(Topo Soft)(ES)[RUN'CAS-'].cas`（SHA-1 aad3641a…） | 逆アセンブルの元。 |
| `Black Beard (1988)(Topo Soft)(ES)[!][RUN'CAS-'][v0.8b].tsx` | **実際のテープ。** ゲームのブロックは Spectrum 形式（TZX の ID 10h）で、独自のローダーを使います。違うのは A5CFh-A66Dh だけ（小ネタ4）。 |
| `Black Beard (1988)(Topo Soft - Kixx)(GB)[RUN'CAS-'][v0.8.2b].tsx` | 実際の Kixx 版テープ。テキスト以外はスペイン版と同じ。 |
| `Blackbeard (…)[Kixx edition][RUN'CAS-'][!].cas` | Kixx 版の .cas。 |
| ディスク `(ES).dsk`、`[a].dsk`、`[a2].dsk` と ROM `(ES).rom` | ディスク・ROM 化版。**3ビットが変わっています**：A7FBh E1→E0、B5BDh 81→01、C8D2h 77→37。 |
| ROM `[h tape2rom Kabish]` | 同様だが、後の2ビットだけ。 |
| ディスク `(ES)(en).dsk` | Kixx とは別の英語テキスト＋3ビット。 |
| ROM `[BetterMSX]` | 大きく組み替えた 64 KB ROM。未解析。 |

**3ビット**は同じコピーから受け継いだダンプの誤りのようです（どれも1ビットだけ変わっています）。

* A7FBh では `POP HL` が `RET PO` になります。直前の `DEC C` で P/V が 0 になるので `RET PO` は必ず実行され、スタック上のデータのアドレスに飛びます。キャラクターの切り抜き処理のこの分岐で、暴走するかゴミを描くはずです（未確認）。
* B5BDh では `ADD A,C` が `LD BC,nn` になり、続く `AND 0FCh` を飲み込みます。プレイヤーと物の位置を比べる処理です。
* C8D2h はデータテーブルの中です。

Computer Emuzone が触れている「MSX 版のバグ」はこれかもしれません。.cas と2本の TSX にはありません。

**Kixx 版**で変わるのは、202バイトのテキスト（9ED0h-A3A0h）と、ステータス表示の BALAS が BULLETS になる部分（6028h-63EEh の42バイト）だけです。Kixx の .cas は各ヘッダの前に 1Fh が1バイト多くありますが、ロードには影響しません。

### テープの構造

1. **TOPO**（BASIC）：`BLOAD"CAS:LOGOTOPO.CM",R`。Topo のロゴアニメ（9470h-A50Dh）。
2. **BLACK**（BASIC）：`BLOAD"CAS:LOAD.BIN"`、`BLOAD"CAS:TEST.BIN"`、`DEF USR=55000`。
3. **LOAD.BIN**（D6D8h）：ローダー。FC9Ah に置いたルーチンから BIOS を呼び、1バイトごとにページ0を BIOS と RAM で切り替えます。
4. **TEST.BIN**（C350h）：ページ0・1・2の RAM を探します。
5. ヘッダなしのブロック4つ（FFh、データ、XOR 1バイト）：
   * 9C40h、7098バイト：ロード画面。続きを読む前に実行されます。色は圧縮（8ラインに1バイト）。
   * 2328h、13000バイト：32x32 のタイル。1枚144バイト（パターン128、色16）。
   * 55F0h、10752バイト：ステータス表示、キャラクター、マップ。
   * 8400h、20479バイト：コード（BA7Dh まで）とデータ。

最後に DI で4ページとも RAM にして 92ACh に飛びます。ゲーム中は BIOS を使わず、0038h に自前の `JP` を書きます。

### ゲーム中のメモリマップ

* 03E8h-1C67h：プレイ画面のバッファ。28バイト x 224ライン（7x7 タイル）。
* 1C68h-1F77h：色バッファ。オリジナルは計算するだけで使いません（小ネタ2）。
* 8E20h-8E6xh：変数（8E26h 残機、8E45h マップのポインタ、8E47h バッファのポインタ、8E23h/8E24h プレイヤーの位置）。
* 900Ch：敵のテーブル（9 x 7バイト）。
* D3FFh-F37Fh：空き。FDE8h：スタック。

### 小ネタ

1. **無限残機の裏技。** ゲーム中に **U・X・Y・Z を同時に押す**（キーボードの行5が 1Bh になる）と、960Ah の `DEC A` が `OR A` に書き換わり、残機が減らなくなります。資料に載っているのは見たことがありません。
2. **プレイ画面はカラーになるはずだった。** `VUELCA_PANTALLA` の最後の `JP`（9BC5h）の後ろに、色テーブルを送るルーチンが残っていて、一度も実行されません。それでもゲームは毎ループ色バッファを計算し（`COLOR_LOSETA`、9CC4h）、時間の約19 %を無駄にしています。有効にするとほとんど黒になります。`CONVIERTE_COLOR`（9C27h）がテーブルでインクを2回引くため、インクと背景が同じ色になるのです。各タイルの色は Spectrum の属性とバイト単位で同じです。
3. **STOP キーの名残。** 9363h で STOP（行7、ビット4）を読んでいますが、その後の分岐は3つの `NOP` に置き換えられています。
4. **忘れられたローダーと、そのままではない .cas。** A5CFh にロードルーチンの使われないコピーがあります。実際のテープ（TSX）では、LOAD.BIN は PSG レジスタ14のビット7を読む Spectrum 風のローダーで、ブロックも Spectrum の形式とタイミングで記録されています。.cas に変換した人が、LOAD.BIN と A5CFh のコピーの両方を BIOS を呼ぶローダーに置き換えました。`-DCINTA_TSX` を付けると 8400h のブロックが TSX と同じになります。
5. **使われない BASIC への復帰。** INICIO は 9667h に BASIC のスタックを保存し、B00Ch にそれを戻して復帰するルーチンがありますが、どこからも呼ばれません。
6. **オリジナルの標準キーは Q・A・O・P とスペース**（9C87h の表）。ジョイスティックも使えます。
7. **Kixx 版の翻訳の誤り：** 「YOUR AMMUNITION GO DOWN AND CANNOT OPEN THE CHEST」「THE TREASURE MAP IN IN YOURS HANDS」、「ESPACIO」は訳されていません。スペイン版は「PORFIN」がつながっています。
8. **メインループが垂直帰線を待たない**ため、画面の内容によって速さが変わります。

### 音楽：MSX、Amstrad、Spectrum

* **MSX と Amstrad の音楽はまったく同じ**です。同じプレーヤー、同じ521バイトのデータ（MSX は 8BF5h、CPC は 226Ah）、同じ94音の表。両方のプレーヤーを15,000フレーム動かすと、PSG のレジスタは（聞こえないノイズを除いて）一致します。曲の長さは69.1秒。
* **MSX は音程が合っていて、Amstrad はほぼ7度低い。** 表は約1.78 MHz の PSG 用に計算されています（最初の音 3405 は MSX で 32.85 Hz の C1）。CPC は PSG が 1 MHz なのに同じ表を使うので、全体が10.1半音低くなります。テンポは同じです。
* 作曲者セサル・アストゥディージョ（Gominolas）によると、意図どおりに鳴っているのは CPC 版です。そのため Enhanced は CPC の音程を使っています（3.10）。
* 60 Hz の MSX では音楽が20 %速くなります。VDP の割り込みで進むためです。
* Spectrum 48K 版はビーパーで別のプレーヤーを使っており、別の編曲・別の調のようです。

## 2. 逆アセンブル

ソースは `src/` にあり、**sjasmplus 1.24.0** 用で約7000行です。`python3 build.py` でスペイン版のテープが**1バイトも違わず**再現されます（SHA-1 で確認）。`python3 build.py kixx` で Kixx 版の4ブロック、`-DCINTA_TSX` で実際のテープの 8400h ブロックができます。

作り方：入口（92ACh、2つの割り込み 8400h と A3CCh、音楽のコマンド表 8926h）からの静的トレース、openMSX でプレイして取ったカバレッジ、手で加えたいくつかの入口（`src/herramientas/z80trace.py`、`hacer.py`、`post2.py`）。結果、10,273バイトがコードになりました。テキストは `db "..."` になります。分かったルーチンにはスペイン語の名前とコメントがあり、残りは `Lxxxx` のままです。

タイルとキャラクターのグラフィック（`graficos/*.bin`）と2つの BASIC はリポジトリにありません。`tools/extrae_originales.py` で手持ちのテープから取り出してください。

### オリジナルの計測（openMSX、ヨーロッパ版 MSX1、PAL）

| | オリジナル |
|---|---|
| 毎秒のループ数 | **5.1**（195 ms、約10フレーム） |
| `DIBUJA_FONDO`（983Dh）：バッファ全体を描き直す | 95.5 ms（49 %） |
| `VUELCA_PANTALLA`（9BA7h）：3 x 1536バイトを VDP に送る | 63.7 ms（33 %） |
| その他すべて | 35 ms |

オリジナルはスクロールしていなくても、毎ループ49枚のタイルをバッファに描き直し、全部を VDP に送ります。スクロールは8ライン単位です。キャラクターはマスク付きでバッファに描かれます。

### キャラクター

ゲームは VDP のスプライトを使わず、キャラクターをマスク付きでバッファに描きます（各ラインに AND マスク N バイトと OR の絵 N バイト）。LAD5Bh が切り抜き、96BAh が 24x24、AC1Fh がその他を描きます。24x24 が 4608h-55C7h に27体、55F0h-59DFh に7体、16x16 の物が19個（59E0h-5ADFh と 5AF0h-5EAFh）、8x8 の弾が 5AE0h にあります。

## 3. 改良版（Enhanced）

新しい部分はすべて `python3 build.py color`（テープ）と `python3 rom/build_rom.py`（ROM）で入ります。特に書いていない限り、ゲームのロジックは変わりません。

### 3.1 基本の高速化（`-DACELERA`）

* 使われない色バッファの計算をやめました。
* VDP への転送を展開し、1バイト47サイクルから32サイクルに（表示中に TMS9918 が必要とする約29サイクルより上）。
* 標準キー：カーソルキーとスペース（H は引き続きポーズ）。従来どおり変更できます。
* 結果：毎秒のループ数が29 %増加。「acelerado」のテープです。

### 3.2 プレイ画面のカラー化（`-DCOLOREA`）

* MSX の90枚のタイルは、16個の属性ごと Spectrum のものと同じです。ゲームはもともと、Spectrum と同じく背景0と1をマップの各マスの色に置き換えていました。
* 256バイトの表（`tabla_color.asm`、`herramientas/tabla_color.py` で生成）で Spectrum の属性を MSX の色に変換します：黒 1、青 4/5、赤 6/8、マゼンタ D、緑 C/3、シアン 7、黄 A/B、白 E/F。
* 各マスは描いたタイルと色を覚えていて、変わらなければ計算し直しません。

### 3.3 キャラクターの下のスプライト（`-DFIGURAS_SPR`）

* 24x24 キャラクターの「白」の部分（マスクが消して絵が描かない所）を、色9（明るい赤）の VDP スプライトで埋めます。プレイヤーはシアン（7）。
* 96BAh が描いたキャラクターを記録します（1ループ8体まで）。パターンは2つのバンク（3800h と 3C00h）を使い、属性は転送の各部分と一緒に送るので、スプライトが絵より先や後になりません。
* キャラクターが重なったときは、バッファを読んでパターンを作り、前にあるキャラクターのインクを隠しません。
* キャラクターの縁は araubi が修正したシート（`graficos/figuras_retocadas_x4.png` → `herramientas/retoque_figuras.py` → `retoque_figuras.asm`）に合わせて削ってあります。変わるのはマスクのビットだけです。
* **薬：** 効いている間（8E3Ch、100ループ）プレイヤーは明るい緑になり、最後の2秒は約0.25秒ごとに緑とシアンで点滅し、シアンに戻ります（`COLOR_JUGADOR`、`desplaza.asm`）。
* **手に持った松明**に色8のスプライトと削った縁（`antorcha.asm`、`herramientas/antorcha.py`）。

### 3.4 部分描画とフレームリミッター（`-DSOLO_CAMBIOS`）

* キャラクターと物は、自分が重なったキャラクター（文字）を記録します。次のループではそこだけをタイルから戻し、VDP にはそれと新しく描いた所だけを送ります（`parcial.asm`）。
* マップの範囲が変わったとき、ウィンドウが動いたとき、何かが独自に書き込んだとき（場面転換、メニュー、テキスト）は、以前と同じく全部やり直します。
* 色は変わった所だけ送ります（`SOMBRA` が VRAM にある内容を覚えています）。
* **リミッター：** 割り込みがフレームを数え、前の転送から5フレーム経つまで次の転送を始めません（100 ms。60 Hz では6フレーム待つのでテンポは同じ）。遅いループの後は、最大1ループ分を取り戻すまで待ちません。ローダーが BIOS の 002Bh をコピーして周波数を知ります。`limite=N` で変更できます。
* **VDP のアドレス設定は DI で：** 割り込みはポート 99h を読むので、アドレスの2バイトの間に割り込むと書き込みが別の場所に行きます（オリジナルにも潜在的に同じバグがあり、ここではステータス表示の瓶が赤くなりました）。

### 3.5 行単位の転送（`-DPORFILAS`）

ゲーム中は 1C00h に行順のネームテーブルを置き、1行ずつパターン、色、その高さで変わるスプライトをまとめて送ります（`filas.asm`、`filas_alto.asm`）。描きかけに見えるのは最大1行で、スプライトが違う背景の上に乗ることもありません。`LESSONS.md` を参照。

### 3.6 プレイヤーを追うスクロール（`scroll.asm`、`desplaza.asm`）

* 192x192 のウィンドウの中央に 72x72 の四角があり、プレイヤーがその中にいる間は画面が動かず、出ると画面が追いかけます。
* **縦は1ドット単位：** バッファには文字4行分の余裕があるので、転送を FINO ライン下から始めるだけです（0-7）。カメラはプレイヤーの一歩（6ドット）ごとに追います（`salto=N`）。SCREEN 2 では各文字が、自分の行の属性を 8-FINO ライン、次の行の属性を FINO ライン使います。
* **横は8ドット単位**（1ドット単位にすると1ループ約90 ms 余計にかかります）。
* **タイルが切り替わるときの引っかかりなし：** マップがちょうど1行か1列動いたときは、バッファをずらして新しい7枚だけを描きます（約92 ms から59 ms に）。
* **大砲：** 松明を持っているとき、発射は大砲の後ろで、ウィンドウがいちばん上のときだけできます。`CANON_QUIETO` がそこと発射中はカメラを止め、発射には新しい砲声が鳴ります（`EFECTO_CANON`）。

### 3.7 MSX2・MSX2+・turbo R

* **裏画面**（`doble.asm`）：002Dh ≥ 1 のとき、VRAM に画面のコピーが2つ（0000h と 4000h）あります。見えていない方に転送し、割り込みでレジスタ 2・4・5・6・10 を切り替えるので、パターン・色・スプライトが同時に現れます。
* **turbo R：** スロット0が拡張されています。TEST.BIN がページ0を BIOS なしのままにして最初の割り込みで止まっていたので、ROM は前もって SLTTBL を保存し、サブスロットを戻します（`REPON_SLOT0`）。さらに CHGCPU を 81h（R800）で呼び、カメラは1ドットごとに追います。
* V9958 のハードウェアスクロール（R#23、R#26/R#27、`hw.asm`）も試しましたが、ステータス表示を組み直す必要があり見た目が悪いため採用しませんでした。ソースには残っています（`build.py ... hw`）。

### 3.8 階段、言語、テキスト

* **階段はボタン不要：** 踏むだけです（`escaleras.asm`）。別の甲板に着いても跳ね返りません。ボタンは常に発射です。
* **メニューで言語：** 「4.- ESPAÑOL」／「4.- ENGLISH」ですべてのテキスト（手描きの Ñ、コード 7Fh）と BALAS/BULLETS の表示が切り替わります（`idioma.asm`。表は E294h-E3FFh）。
* 英語を修正：「YOU HAVE RUN OUT OF AMMO AND CANNOT OPEN THE OTHER CHESTS」「BE MORE CAREFUL NEXT TIME」「THE TREASURE MAP IS AT LAST IN YOUR HANDS」。スペイン語は「POR FIN」。

### 3.9 ステータス表示の塗り直し（`-DMRUBEN`）

araubi がステータス表示（どくろ、瓶、帽子と上着の肖像、顔とオウム）を塗り直しました。SCREEN 2 では8ドットの1ラインに2色までなので、3色あるラインはいちばん近い色に合わせました（`graficos/marcador_ruben_ajustado.png` → `herramientas/marcador.py` → `marcador.asm`）。

### 3.10 CPC の音程の音楽（`-DAFINA_CPC`）

音の表（8866h、96周期）を1.7897725倍します（`afina_cpc.asm`、`herramientas/afina_cpc.py` で生成）。7,176音すべてが CPC と同じ周波数になります（ずれは最大13セント）。`musica_msx` で MSX の音程のままにできます。

### 3.11 ROM

* **64 KB、ASCII16 メガロム。** BlueMSX は 4000h に「AB」のない 64 KB ROM をすべて ASCII16 とみなし、openMSX は 77FFh への書き込みから判断するので、どちらも自動で認識します。バンク0は 4000h、バンク1（ロゴとページ3に行くもの）とバンク2（タイル）は 8000h。バンクの切り替えは ROM がまだページ1にある間に行います。
* **v1.1、どのメガロム方式でも動作**（`src/rom/multimapper.asm` と `multimapper.py`、`build_rom.py` が適用）。One Chip MSX では SD から ROM を読み込むプログラムがメガロム方式を推測します。SofaROM は「wide」の ASCII8 と判断し（ページ切り替えと思われる `LD (nn),A` 命令にパッチを当て、圧縮データ内の偽物も対象になります）、mglOCM は Konami と判断していました。現在は ARRANQUE が 6800h に 1 を書き（ASCII8 はページ0が 6000h にも見えた状態で起動することがある）、前半の空き領域（7A60h）にあるインストーラを呼び、ルーチンを E580h にコピーします。DETECTA は 6000h に 3 を書いて 4000h を読みます：バンク3の目印 16h なら ASCII16、ROM の 6000h のバイトなら ASCII8、どちらでもなければ 5000h に 3 を書き、変われば Konami SCC、変わらなければ Konami。PAG2 はそれぞれのレジスタ（7000h、7000h/7800h、9000h/B000h、8000h/A000h）で 16K バンクを 8000h に置き、書き込みは常に `LD (HL),n` で行います。openMSX に ASCII16 と判断させる埋め草は `LD (7000h),A` と `LD (6000h),A` だけを使います。77FFh のようなアドレスがあると SofaROM が「wide」モードになるためです。openMSX で4方式すべて、実機の OCM（KdL 3.9.2）で mglOCM を使って確認済み。
* ブロックは **ZX0** で圧縮（Einar Saukas。展開ルーチンは Einar Saukas と Urusergi、3条項 BSD ライセンス、`src/rom/LICENSE_ZX0.txt`）。
* テープと同じことをします：`COLOR 1,1,1:SCREEN 2`、Topo のロゴ、ロード画面、ゲーム。RAM を探すのにテープの TEST.BIN をそのまま使うので、64 KB が必要です。
* openMSX で C-BIOS（ヨーロッパ版と日本版の MSX1、MSX2、MSX2+）と、HB-20P・HB-F900・FS-A1ST・FS-A1GT の実 BIOS で確認：92ACh に着いた時点の RAM はテープの場合と（周波数のバイトを除いて）同じで、VRAM の検証でもエラーはありません。

## 4. 速さ：オリジナルと Enhanced

openMSX、MSX1 PAL（C-BIOS）、オリジナルのテープと ROM で同じキー操作。メインループ（9317h）1回あたりの 50 Hz のフレーム数：

| 状況 | オリジナル | Enhanced | 1ループの時間 | 毎秒のループ数 |
|---|---|---|---|---|
| 静止 | 9.20 | 5.04 | −45 % | +83 % |
| 歩行 | 9.28 | 5.37 | −42 % | +73 % |
| 階段（縦スクロールあり） | 9.31 | 5.74 | −38 % | +62 % |
| **平均** | **9.30** | **5.25** | **−44 %** | **+77 %** |

48ドット歩くのは1.46秒から0.80秒に、階段を90ドット上るのは2.82秒から2.14秒になりました。最小5フレームはリミッターによるものです。スクリプトは `tools/velocidad/` にあります。

## 5. テスト方法

* `src/openmsx/verif_parcial.tcl`：毎ループ、VRAM（パターン、色、ネームテーブル）をゲームのバッファと比べます。HB-20P、HB-F900、FS-A1ST、FS-A1GT で、両方向にスクロールしながら何千ループも差はありませんでした。起動用：`tools/pruebas/vp.sh`。
* `src/openmsx/cinta.tcl` ＋ `cas_prep.py`：テープを待たずに読み込み（TAPION/TAPIN にブレークポイント）、92ACh で RAM をダンプします。`compara_rom.py` でブロックと比較します。
* `src/openmsx/analiza.py`：スプライトがキャラクターの背景と一致し、インクを隠さないことを確認します。
* openMSX の `.omr` リプレイ：プレイ中に見たバグを再現するため、スナップショットを新しい ROM に入れ、ビルド間で違うバイトだけを移植します。
* 50 Hz の C-BIOS マシンは `src/openmsx/*.xml`（ROM は `tools/cbios50.py` で作成）。
